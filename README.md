# TASCA — интерактивный MVP 0.4

Сайт-прототип сервиса небольших оплачиваемых задач для студентов и малого бизнеса. Основан на wireframes TASCA из Figma и расширенной логике прототипа Андрея. Версия **0.4** упрощает интерфейс и добавляет два вида просмотра: **телефон** и **компьютер**.

## Как открыть

Не нужно устанавливать React, Node.js или дополнительные пакеты. Достаточно открыть `index.html` в браузере. Если хотите редактировать через VS Code, удобно запускать через **Live Server**.

Если работаете через терминал на Mac:

```bash
cd путь/к/папке/TASCA_MVP_04
python3 -m http.server 8000
```

Затем зайдите на `http://localhost:8000`.

## Переключатель вида

В правой панели **«Просмотр»** выберите:

- **Телефон** — сайт показан в корпусе смартфона (~390 px), карточки расположены в одну колонку.
- **Компьютер** — рамка смартфона исчезает, область сайта расширяется, каталог перестраивается в две колонки, навигация становится горизонтальной.

Переключение **не сбрасывает выбранную роль, страницу или заполненные данные**. На настоящем смартфоне сайт всегда занимает доступную ширину экрана, независимо от выбранного демо-режима. На компьютере при скрытии боковых подсказок переключатель остаётся сверху справа.

Ссылки для предпросмотра: `?view=desktop` — открывает компьютерный вид; `?demo=0` — скрывает боковые панели; можно сочетать `?view=desktop&demo=0`.

## Что упрощено

- Короткий экран знакомства с сервисом вместо нескольких больших объясняющих блоков.
- Карточки задач показывают главное: категорию, сумму, название, заказчика и срок. Подробное ТЗ видно после нажатия.
- Фильтры спрятаны за кнопкой рядом с поиском.
- Условия приёмки, портфолио, сведения о заказчике и переписка открываются по желанию.
- В интерфейсе выделены основные действия; демо-кнопки имитации «другой стороны» вынесены в раскрываемый раздел **«Продолжить тест»**.
- На экране заказчика задания собраны по статусам; формы и навигация стали компактнее.

## Тестовые сценарии

**Студент:** начать → профиль → лента → карточка задачи → отклик → подтверждение выбора → выполнение → сдача → проверка → отметка о завершении → отзыв.

**Заказчик:** начать → профиль → создать задание → модерация (демо) → увидеть отклики → выбрать студента → начать задачу → проверить результат → принять или запросить правки → отметить завершение → отзыв.

Обе стороны можно пройти в одном браузере, используя **«Сменить роль»**. Данные демо-пользователей, задач и сообщений сохраняются в `localStorage` данного браузера; между разными устройствами они не синхронизируются. Кнопка **«Начать заново»** сбрасывает данные.

**Обязательно:** это только локальная симуляция. Настоящих пользователей, платежей, банковского резервирования, чатов между людьми и серверной модерации здесь нет. Все учебные примеры и автоответы синтетические.

## Как запушить на GitHub

1. Создайте пустой репозиторий, например `tasca-mvp`.
2. Откройте папку с распакованными файлами проекта в терминале VS Code.
3. Выполните (вместо `USERNAME` укажите свой логин GitHub):

```bash
git init
git add .
git commit -m "TASCA MVP 0.4 — simplified UI and device preview"
git branch -M main
git remote add origin https://github.com/USERNAME/tasca-mvp.git
git push -u origin main
```

Если репозиторий уже существует, не повторяйте `git init` и `git remote add origin`; вместо этого достаточно `git add .`, `git commit -m "Update TASCA MVP"`, `git push`.

4. На GitHub откройте **Settings → Pages → Build and deployment → Deploy from a branch** и выберите **main / (root)**. GitHub Pages опубликует `index.html`.

Относительные пути уже настроены для Pages, сборка не нужна.

## Структура проекта

```text
index.html         HTML-каркас, симулятор телефона, боковые панели
styles.css         Адаптивные стили для телефона и компьютера
app.js             Сценарии студента и заказчика, локальные данные
presentation.js    Переключатель «Телефон / Компьютер», панели тестирования
MVP_PLAN.md        Гипотезы, метрики, дорожная карта
TESTING.md         Инструкция по проверке
CHANGELOG.md       История изменений
previews/          Скриншоты обоих режимов
```

Необязательные автоматические проверки: `test_ui_v04.py` и `test_cross_role.py` (Python, Playwright, Chromium). Для размещения на GitHub Pages они не нужны.
